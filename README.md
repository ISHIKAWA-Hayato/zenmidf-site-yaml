# zenmidf 駅別ページ（YAML 生成方式）

zenmidf.jp の駅別ページを、駅データ（YAML）からテンプレートで生成し、GitHub Actions でロリポップへ自動アップロードする仕組み。
**このリポジトリが駅別ページの正本**。対象の会社のページを、旧フォルダの HTML や FTP で直接直さない（次の自動アップロードで上書きされる）。

## 対象（2026-11-10 時点）
| 会社 | フォルダ | 駅数 |
|---|---|---|
| JR西日本 | `data/04-West-Japan/` | 252 |
| JR四国 | `data/05-Shikoku/` | 36 |
| JR九州 | `data/06-Kyushu/` | 204 |
| 私鉄・三セク 9社 | `data/99-Others/21-Izukyu/` ～ `37-Hokuetsu-Kyuko/` | 63 |

JR北海道・JR東日本・JR東海（01〜03）は未対応で、これまでどおり手書きの HTML を FTP で上げる。

## ふだんの流れ
```
YAML を直す → push → Actions：（駅写真の取り込み）→ 生成 → ロリポップへアップロード
```
- **作業の前に必ず pull**。GAS（駅写真の送信）や Actions（写真の取り込み結果）がリポジトリに直接コミットする
- 駅データの書き方・決まりごとは `AGENTS.md`（AI に頼むときもこれに沿う。Claude Code は `CLAUDE.md` 経由で読む）
- 新しい駅の実装や大きな変更のあとは、DF スプレッドシートと照合する（下記）

### 駅写真
`inbox/` に `<会社番号2桁>-<駅ID>.png` を置く（共有ドライブの「受付」に置けば GAS が1時間おきに送る。名前がなくても位置情報・OCR で駅を当てる）と、Actions が 800×600 PNG にして `data/<会社>/images/` に入れ、駅データの `画像:` も直して本番に出す。詳しくは `docs/images-guide.md`。

## フォルダ
- `data/<会社フォルダ>/` … 駅データ（1駅1ファイル）と一覧データ `_index.yaml`
- `data/<会社フォルダ>/images/` … 駅写真（800×600 PNG）。ビルドでそのまま dist にコピーされ、アップロードされる
- `data/99-Others/` … 私鉄・三セク。サイトと同じく1段深い。入口ページ（99-Others.html）は `_portal.yaml` から生成し、配下の会社がフォルダ名順に並ぶ（入口での会社名は `_index.yaml` の `入口表示名` で変えられる）
- `inbox/` … 駅写真の受け口。取り込めなかったものは `inbox/_error/` に理由（.txt）付きで残る
- `templates/` … ページの型（`base.html` が全ページ共通の外枠、`station.html` 駅、`company.html` 会社一覧、`portal.html` 入口）
- `site.yaml` … メニュー・サイト名・ファビコンなど全ページ共通の設定
- `pages/` … トップ階層のページ（ホーム・駅別ページ・About US・サポート・DF検索・リンク集・エラーページなど16枚）。本文はHTMLのまま、メニューだけ `site.yaml` から入る（2026-11-11 に公開中のものを取り込み）
- `tools/` … 道具（下記）
- `gas/drive_to_inbox.gs` … 共有ドライブ「受付」→ `inbox/` の GAS（GAS 側に貼って使う。ここは控え）
- `original/` … JR四国の YAML 化のときに比較に使った公開中ページ（2026-11-09時点）
- `docs/deploy-guide.md` … 自動アップロードの設定・FTP パスワードを変えたとき・戻し方
- `docs/images-guide.md` … 駅写真のファイル名のルールと共有ドライブ連携の設定
- `.github/workflows/deploy.yml` … 自動アップロード（写真の取り込み → 生成 → FTPS）
- `dist/` … 生成結果（GitHub には送らない）／ `zenmidf.xlsx` … DF の写し（GitHub には送らない）

## 道具
```
pip install pyyaml jinja2 beautifulsoup4 html5lib pillow openpyxl
```
| コマンド | 内容 |
|---|---|
| `python tools/build.py` | `data/` から `dist/` に生成（Actions でも同じものを動かす） |
| `python tools/check_df.py --changed` | origin/main から変えた駅を DF と照合（`-s 駅ID`、`-c 会社フォルダ`、`--missing` で未実装の駅も） |
| `python tools/make_coords.py <N02のzip>` | 国土数値情報から駅の座標表 `data/_coords.csv` を作る（写真の駅の自動判定用） |
| `python tools/import_images.py` | `inbox/` の写真を取り込む（ふだんは Actions が動かす） |
| `python tools/html2yaml.py <駅ページのフォルダ> <出力フォルダ>` | 旧 HTML の駅ページ → 駅データ |
| `python tools/index2yaml.py <一覧HTML> <駅データフォルダ> <会社コード> <アイコン規則YAML>` | 旧 HTML の会社一覧 → `_index.yaml` |
| `python tools/compare.py <元HTMLのフォルダ> <dist の会社フォルダ>` | 元ページと生成ページの `<main>` を見た目の単位で比較 |

### DF スプレッドシートとの照合
スプレッドシートを「ファイル → ダウンロード → Microsoft Excel (.xlsx)」で保存し、リポジトリ直下に `zenmidf.xlsx` として置く（古い写しを残さない）。
駅×シート単位で、設備の有無・機種・端末数・営業時間・営業形態・駅員配置・廃止済／掲載外との矛盾を報告する。YAML もシートも書き換えない。私鉄・三セクの自社 POS は DF の対象外なので照合しない。

## 会社を増やすとき
1. 旧 HTML を `html2yaml.py` で駅データに、`index2yaml.py` で `_index.yaml` に変換（アイコン規則は既存の会社を参考に。機種で分けるなら5つ目の要素）
2. `build.py` で生成し、`compare.py` で元ページと全ページ比較。食い違いは「直す」か「意図した変更として記録する」かを決める
3. `check_df.py` の会社対応表（DF の「所属会社」→ フォルダ）に足す
4. 他社の一覧からその会社の駅へのリンクがあれば `{他社駅: <会社フォルダ>/<駅ID>}` に置き換える
5. 以後その会社のページは旧フォルダで直さない

- **JR四国（2026-11-09）**：駅ページ 36/36・一覧 1/1 が見た目の単位で元と一致。一覧アイコンは全41か所が駅データからの自動判定で一致
- **JR西日本・JR九州（2026-11-09 変換、2026-11-11 検証）**：手元の元 HTML と変換時点（fd5d783）の生成結果を比べ、駅ページは JR西日本 252/252・JR九州 204/204 が見た目の単位で元と一致。一覧は次を除いて一致し、いずれも変換後を正とした
  - JR九州：みどりの窓口がある駅の POS アイコンを外した（門司港・小倉・赤間・博多・佐賀・唐津・別府。アイコン規則の「みどりの窓口があれば数えない」による）

  - 南行橋・新田原は変換後に元の一覧へ足されたもので、別途反映済み
  - 変換後に変わった駅ページ（139駅）は、すべて個別のコミット（写真の追加・データ更新・「係員」への表記統一）で説明がつく
- **私鉄・三セク9社（2026-11-09）**：63駅＋各社一覧＋入口ページの `<main>` が、次の意図した変更を除いて元と一致。JR3社の生成結果は変更前と同一
  - 駅画像の段落にあった「JR西日本○○駅は<a>こちら</a>」（加賀温泉・金沢・小松・富山）を、画像の下の段落（駅注記の `他社ページ`）にそろえた

- **全社共通で意図的に統一した外枠**：ファビコン（駅ページの `../../images/fav.jpg` はサーバーに存在しない）→ `/images/fav.png`、フッターの旧サイト名「全国「みどりの窓口」データファイル」→ サイト名
