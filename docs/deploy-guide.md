# 自動アップロード導入の手引き（JR四国）

データ（YAML）を直して GitHub に送ると、GitHub が自動でページを生成し、ロリポップへ FTP でアップロードする仕組みを作る。
対象は **data/ にある会社（JR西日本・JR四国・JR九州）の駅ページと一覧だけ**。ほかの会社・トップページ・駅写真には触れない。

```
YAMLを編集 → GitHubに送る（push） → GitHub Actions が生成 → ロリポップへFTPSでアップロード
```

所要時間の目安：初回 1〜1.5 時間。以下の順番どおりに進めること。

---

## 1. ロリポップ側の確認（ロリポップのユーザー専用ページ）

### 1-1. FTP の接続情報を控える
「ユーザー設定」→「アカウント情報」で次の2つを確認する。**パスワードはこの手引きやチャットに書かない。**
- FTP・WebDAV アカウント（＝FTPユーザー名）
- FTP・WebDAV パスワード
- サーバーは `ftp.lolipop.jp`（暗号化方式は Explicit FTP over TLS ＝ FTPS）

### 1-2. 「FTPアクセス制限」が無効になっているか確認する
「セキュリティ」→「FTPアクセス制限」。ここに IP アドレスを登録して制限していると、GitHub からの接続は毎回 IP が変わるため **必ず失敗する**。
- 制限していなければそのままでよい
- 制限している場合は、自動アップロードを使うなら解除が必要（解除するかどうかは要判断）

※「海外アタックガード」は WordPress の管理画面などが対象で、FTP には関係しない。

### 1-3. サーバー上の四国フォルダの場所を控える
いつも使っている FTP ソフトで接続し、`05-shikoku.html` が入っているフォルダの **ログイン直後の場所からの道のり** を控える。
例：`station-individual/05-Shikoku/` や `zenmidf/station-individual/05-Shikoku/`
- 先頭に `/` は付けない、末尾には必ず `/` を付ける

### 1-4. バックアップを取る
そのフォルダ（`05-Shikoku`）を丸ごと PC にダウンロードしておく。何かあったらこれを上げ直せば元に戻る。

---

## 2. GitHub の準備

### 2-1. アカウント作成
https://github.com でアカウントを作る（既にあれば不要）。サークル用に別アカウントを作るかは任意。

### 2-2. GitHub Desktop を入れる
https://desktop.github.com から入れて、作ったアカウントでサインインする。
（VS Code の「ソース管理」でも同じことができる。慣れている方でよい）

---

## 3. リポジトリを作って送る

1. GitHub Desktop で「File」→「Add local repository」→ `C:\Users\hayat\work\zenmidf-proto` を選ぶ
2. 「このフォルダはリポジトリではない」と出たら「create a repository」を押す（名前は `zenmidf-site` など）
3. 左下の Summary に「最初の登録」と書いて「Commit to main」
4. 上部の「Publish repository」を押す。**「Keep this code private」にチェックが入っていることを必ず確認**してから Publish

`dist/` と zip ファイルは送られない設定（`.gitignore`）になっている。

---

## 4. 接続情報を GitHub に登録する

ブラウザで作ったリポジトリを開き、「Settings」→「Secrets and variables」→「Actions」。

### Secrets タブ（他人に見えない値）
「New repository secret」で2つ登録する。
| 名前 | 値 |
|---|---|
| `FTP_USERNAME` | 1-1 の FTP アカウント |
| `FTP_PASSWORD` | 1-1 の FTP パスワード |

### Variables タブ（設定値）
「New repository variable」で2つ登録する。
| 名前 | 値 |
|---|---|
| `DEPLOY_ALL` | `false` |

`DEPLOY_ALL` が `true` になるまでは、何をしても **試運転（アップロードしない）** になる安全装置。
アップロード先は `html/station-individual/`（設定ファイルに直接書いてある）。

※ 四国だけで運用していた時期の変数 `SERVER_DIR_SHIKOKU` / `DEPLOY_ENABLED` はもう使っていない。消してよい。

---

## 5. 試運転

1. リポジトリの「Actions」タブ →「生成してロリポップへアップロード」→「Run workflow」→ そのまま実行
2. 数十秒で終わる。緑のチェックが付いたら実行結果を開き、「JR四国をアップロード」の行を開いて次を確認する
   - ロリポップに接続できている（`Connected` などの表示）
   - アップロード予定が **495 ファイル**（西日本 253・四国 37・九州 205）前後
   - **削除（delete）予定が 0 件**  ← ここが 0 でなければ本番に進まない
3. 赤い × で失敗したら、ログの最後の数行をそのまま Claude に渡す

よくある失敗：
- 接続できない → 1-2 の FTP アクセス制限、または Secrets の打ち間違い
- 場所が違う → `SERVER_DIR_SHIKOKU` の先頭 `/` の有無・末尾 `/`

---

## 6. 本番

1. Variables の `DEPLOY_ALL` を `true` に変える
2. 「Run workflow」で **「試運転」のチェックを外して** 実行
3. サイトを開いて、四国の一覧といくつかの駅（高松・朝倉・窪川など）を目で確認する
   - ファビコンが出るようになっているはず（元は 404 だった）

以後は、`data/` などを変えて main に送る（push）だけで自動で本番アップロードされる。

初回アップロード後、サーバーの四国フォルダに `.ftp-deploy-sync-state.json` というファイルができる。
どのファイルを上げたかの記録で、次回から変更分だけを上げるのに使う。消さないこと。

---

## 7. ふだんの更新

1. `data/05-Shikoku/<駅>.yaml` を直す（書き方は `CLAUDE.md` の表を参照）
2. GitHub Desktop で Commit → Push
3. Actions タブで緑のチェックを確認

Claude に任せるとき：
- 変更内容（掲示の写真やメモ）と、該当する YAML を渡して「直して」と頼む
- リポジトリを Claude のセッションにつなげば、Claude が直接直して変更を提案できる（このプロジェクトのチャットで相談）

## 8. FTP パスワードを変えたとき
1. ロリポップでパスワードを変える
2. GitHub の Settings → Secrets and variables → Actions で `FTP_PASSWORD` を新しい値に更新する（忘れると自動アップロードが失敗する）
3. 新しいパスワードは Secrets 以外（この手引き・チャット・コミット）に書かない

変更記録（値は書かない）:
- 2026-11-10 変更（旧パスワードは無効）
- 2026-11-11 リポジトリを公開用に作り直した（それまでの履歴は非公開の `zenmidf-site-yaml-old` にアーカイブ）。公開リポジトリなので、パスワード・ユーザー名・トークンなどの値はファイルにもコミットにも書かない

## 9. 戻したいとき
- GitHub Desktop の「History」で戻したいコミットを右クリック →「Revert changes in commit」→ Push（前の状態が自動で上がる）
- 仕組みごと止めたいときは `DEPLOY_ALL` を `false` に戻し、1-4 のバックアップを手で上げ直す

---

## 注意
- この仕組みが上げるのは data/ にある会社の駅ページ・一覧・駅写真（`images/`）。駅写真の更新は `docs/images-guide.md`
- 四国の駅ページは今後 **手で直接編集しない**。手で直すと次の自動アップロードで上書きされる
- ほかの会社に広げるときは、その会社のデータ化（逆変換）と比較確認を先に済ませてから
