# 駅写真の更新手引き

駅写真は `data/<会社フォルダ>/images/` にあり、駅データの `画像:` から参照される（例 `画像: images/takaoka.png`）。
写真は **inbox/ に置けば自動で反映** される。置き方は3通りで、後ろの処理は同じ。

```
共有ドライブ「受付」 ─(GAS・1時間おき)─┐
GitHub の inbox/ に直接アップロード ────┼→ GitHub Actions：800×600 PNG に変換 → data/<会社>/images/ → 駅データの 画像: を更新 → 本番へアップロード
Claude に写真を渡す ────────────────────┘
```

## ファイル名のルール（メンバーへの案内用）
`<会社番号2桁>-<駅ID>.<拡張子>`　例：`32-takaoka.png`　`06-sasabaru.jpg`　`05-san_takamatsu.heic`

| 会社番号 | 会社 |
|---|---|
| 04 / 05 / 06 | JR西日本 / JR四国 / JR九州 |
| 21 / 22 | 伊豆急行 / WILLER TRAINS |
| 31 / 32 / 33 / 34 | IRいしかわ鉄道 / あいの風とやま鉄道 / えちごトキめき鉄道 / 土佐くろしお鉄道 |
| 35 / 36 / 37 | のと鉄道 / ハピラインふくい / 北越急行 |

- 駅IDは **駅ページのURLの末尾**（`.html` の前）と同じ。例 `…/32-Ainokaze-Toyama/takaoka.html` → `takaoka`
- 写真は **4:3 の横長**。3%以上ずれていると取り込まない（縦写真・16:9 は切り抜いてから）
- PNG / JPG / HEIC（iPhone）/ WebP。スマホの回転情報は自動で直し、位置情報などのメタデータは消える
- 写真がない駅には新しく付く。**すでに写真がある駅は上書きしない**（`inbox/_skipped/` に理由付きで残る。失敗扱いにはしない）
- 差し替えたいときは駅IDの後ろに `!` を付ける：`06-isahaya!.png`
- JR北海道・東日本・東海（01〜03）はまだ対象外

### 名前を付けずに「受付」に置いた場合（自動判定）
`IMG_1234.JPG` のような名前のままでも、GAS が駅を当てて名前を付け直す。
1. 写真の **位置情報**（撮影地点）から 600m 以内で一番近い駅
2. 近い駅が複数あるときは、写真の文字を **OCR** で読んでその中から駅名を探す（駅舎の「○○駅」を最優先、次にローマ字、駅名だけ）
- **位置情報がない写真は自動では決めない**。OCR で読めた駅名を説明に書いて「要確認」に移すので、人が確かめて名前を付け、「受付」に戻す（読み違いで別の駅に写真が付くのを防ぐため）
- 1駅に決まれば `06-isahaya.jpg` のように名前を変えて送る。ファイルの説明に「自動判定: 位置情報（駅から120m）」などの根拠が残る
- 決まらなければ共有ドライブの「**要確認**」に移り、ファイルの説明に理由と候補が書かれる。正しい名前に変えて「受付」に戻せば次の回で送られる
- 看板の「○○駅」は読めたが、サイトにまだ駅ページがない駅（JR東日本・東海、JR西日本の未着手の地域など）は「**未実装**」フォルダに移る（`PENDING_FOLDER_ID` がなければ「要確認」）。その駅をYAML化したら、名前を付けて「受付」に戻す
- 「要確認」の写真と理由は、GAS の `listReview` を実行すると実行ログに一覧される
- JR と三セク、JR 2社で同じ駅名のページがある駅（博多・富山・金沢など）は会社が決まらないので必ず「要確認」になる
- LINE や Discord を通した写真は位置情報が消えていることが多い。駅名が写っていない写真（窓口の中など）は当たらない
- 駅の一覧と座標はサイトの `station-individual/stations.json`（build.py が作る）を読む。座標の元は `data/_coords.csv`（下記）

取り込めなかった写真は GitHub の `inbox/_error/` に移り、同名の `.txt` に理由が書かれる。その実行は Actions で失敗（赤）になり、通知が届く。直したら `_error` のものは消してよい。

## 共有ドライブ ↔ GitHub の設定（初回だけ）

### 1. 共有ドライブにフォルダを5つ作る
「受付」「取り込み済み」「エラー」「要確認」「未実装」。メンバーには「受付」だけ使ってもらう。各フォルダを開いたときの URL の `folders/` の後ろがフォルダID。

### 2. GitHub のトークンを作る
GitHub → Settings → Developer settings → Personal access tokens → **Fine-grained tokens** → Generate new token
- Repository access：**Only select repositories** → `zenmidf-site-yaml` だけ
- Permissions → Repository permissions → **Contents：Read and write**（ほかは不要）
- 有効期限を決めて作成し、表示されたトークンを控える（**チャットや手引きに貼らない**）。期限が来たら作り直してプロパティを差し替える

### 3. GAS を作る
**`drive_to_inbox.gs` をドライブにアップロードしても動かない**（ただのテキストファイルとして置かれるだけ）。Apps Script のエディタで新しいプロジェクトを作り、中身を貼り付ける。
1. ブラウザで **script.google.com** を開き、左上の「**新しいプロジェクト**」（ドライブの「新規 → その他 → Google Apps Script」でも同じ）。プロジェクトは自分のマイドライブにできる
   - 共有ドライブの中には作らない（メンバーがトークンを読めてしまう）
   - ドライブの「プロジェクト」機能（ファイルをまとめる機能）とは別物。そこに入れる必要はない
2. 左上の「無題のプロジェクト」を「zenmidf 写真受付」などに変える
3. 手元の `gas/drive_to_inbox.gs` をメモ帳で開いて全部コピーし、エディタの「コード.gs」の中身（`function myFunction() {}`）と置き換えて保存
4. 左の歯車「プロジェクトの設定」→ 下の方の「スクリプト プロパティを追加」で次を登録
   - `GITHUB_TOKEN`：2 のトークン
   - `GITHUB_REPO`：`ISHIKAWA-Hayato/zenmidf-site-yaml`
   - `INBOX_FOLDER_ID` / `DONE_FOLDER_ID` / `ERROR_FOLDER_ID` / `REVIEW_FOLDER_ID`：1 のフォルダID（`REVIEW_FOLDER_ID` がないと自動判定はせず、名前の形が違うものは「エラー」に回る）、`PENDING_FOLDER_ID`：「未実装」のフォルダID（任意）
5. 自動判定を使うので、エディタ左の「**サービス**」の＋ →「**Drive API**」を選んで追加する
6. エディタ上部の関数の選択欄で `setupTrigger` を選んで「実行」。初回は権限の確認が出る。「このアプリは Google で確認されていません」と出たら「詳細」→「（安全ではないページ）に移動」で進める（自分のスクリプトなので問題ない）。以後1時間おきに `sendInbox` が動く
7. 試すときは「受付」に1枚置き、関数の選択欄で `sendInbox` を選んで「実行」→ GitHub の Actions に実行が出ればつながっている

GAS は写真をドライブの縮小画像（長い辺 800px の JPEG）にして送る（元の写真を送るとリポジトリの履歴が重くなるため）。1回の実行は4分半で区切り、1回に最大100枚。たくさん溜まっているときは `sendInbox` を手で何回か実行すれば早く片付く。

GAS 側で名前の形が違うものは共有ドライブの「エラー」に移り、ファイルの詳細（説明）に理由が出る。送れたものは日時を頭に付けて「取り込み済み」に移る。

## 駅の座標表（`data/_coords.csv`）
写真の位置情報から駅を当てるための緯度・経度の表。国土数値情報「鉄道」（N02）から作る。
- 駅ページのある駅は駅IDごとに1行
- **JR全6社と data/99-Others の会社は、駅ページのない駅も全駅載せる**（「駅ID」は空、「照合」は `国土数値情報（ページなし）`、「路線」付き）。ページのない駅で撮られた写真が、近くのページのある駅に誤って付かないようにするため。そう判定された写真は「未実装」に移り、説明に「○○（JR東日本・○○線）」のように会社と路線が書かれる
1. 国土数値情報のダウンロードサイトで「鉄道」（N02）の最新年度・全国の zip をダウンロードし、リポジトリ直下に置く（`*.zip` は GitHub に送られない）
2. `python tools/make_coords.py N02-25_GML.zip`（ファイル名は版に合わせる）
3. 最後に出る「手で座標を入れる必要がある駅」は、Googleマップで駅を右クリックして出る緯度・経度を書き、「照合」を `手入力` にする（作り直しても上書きされない）
   - 「改名などで突き合わせ損ねた疑いのある駅」は、ページのある駅のすぐ近くに名前の違うページのない駅が出たもの。同じ駅なら、ページのない駅の行の「照合」を `除外` にし（作り直しても載らなくなる）、ページのある駅の行を `手入力` で直す
4. 駅を増やしたとき・会社を増やしたときに作り直す

- いまの表は **N02-20（2020年）** から作っている。2024年3月に JR 北陸線から移った区間は、`make_coords.py` の `TRANSFERS` で付け替えている（敦賀〜大聖寺の手前 → ハピラインふくい、大聖寺〜金沢 → IRいしかわ鉄道。敦賀・金沢は JR西日本にも残す）。新しい版の N02 に変えたら、移管後のデータなので付け替えは自動で働かなくなる
- **2020年より後にできた駅**（新幹線の新駅など）は表にないので、手で行を足す。ページのある駅は駅IDを書き、ページのない駅は駅IDを空にして「路線」を書く。どちらも「照合」は `手入力`（作り直しても消えない）
- 2020年より後に廃止された駅は表に残っている（その駅の写真は「未実装」に回るだけで害はない）。消したいときは「照合」を `除外` にする

## 注意
- Actions が取り込み結果をリポジトリに書き戻すので、**手元で作業を始める前に必ず pull** する
- サーバーにしかない写真（手元にない古い写真）は消えない
